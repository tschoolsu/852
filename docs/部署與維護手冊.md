## 部署前必須先決定

### 程式是否確定搬到 Debian

狀態：`待決定`

需要選擇：

1. 繼續使用目前的 Cloudflare Workers、D1、R2。
2. 將程式搬到 Debian、PostgreSQL、Nginx、PM2。

如果選擇繼續使用 Cloudflare：

- 不需要安裝 Debian 主機。
- 不需要 PostgreSQL。
- 不需要 Nginx。
- 不需要 PM2。
- 只需要設定自訂網域、SMTP、備份及管理員功能。

如果選擇 Debian：

- 必須先完成 Node.js 執行版本。
- 必須將 D1 資料庫程式改為 PostgreSQL。
- 必須完成資料遷移。
- 必須決定檔案儲存方式。
- 必須測試登入、權限、版本、垃圾桶及下載功能。

### 檔案儲存方式

狀態：`待決定`

可以選擇：

#### 保留 Cloudflare R2

優點：

- 檔案不依賴單一主機磁碟。
- Debian 主機故障時，檔案仍保存在 R2。
- 可以維持私有 Bucket。
- 不需要將大量檔案放在主機備份中。

需要完成：

- 建立 R2 API 金鑰。
- 限制金鑰只能存取指定 Bucket。
- 將金鑰放入正式環境變數。
- 測試上傳、下載、替換、版本及刪除。

#### 改用 Debian 主機磁碟

優點：

- 架構較直接。
- 不需要另外連接 R2。

風險：

- 主機磁碟故障可能造成檔案遺失。
- 必須自行備份所有檔案及版本。
- 主機容量不足會造成上傳失敗。
- 多台主機無法直接共用同一份檔案。

如果使用主機磁碟，建議目錄：

```text
/srv/tfiles/storage/current
/srv/tfiles/storage/versions
```

檔案目錄不得放在 Nginx 的公開網站目錄。

## Debian 12 初始化

狀態：`架構確認後可執行`


```bash

```

確認：

- 作業系統為 Debian 12。
- 系統更新已完成。
- 重新啟動後可以正常連線。
- 系統時間及時區正確。

設定台灣時區：

```bash
sudo timedatectl set-timezone Asia/Taipei
```


### 安全更新

Debian 提供 `unattended-upgrades` 自動安裝安全更新。

啟用前應先確認：

- 學校是否允許自動更新。
- 是否有維護時間。
- 更新後服務是否需要重新啟動。
- 是否有人負責查看更新失敗通知。

啟用設定：

```bash
sudo dpkg-reconfigure unattended-upgrades
```

### 建立程式帳號

不要使用 `root` 執行網站程式。

建立系統帳號：

```bash
sudo adduser --system \
  --group \
  --home /srv/tfiles \
  --shell /bin/bash \
  tfiles
```

建立目錄：

```bash
sudo install -d -o tfiles -g tfiles /srv/tfiles/app
sudo install -d -o tfiles -g tfiles /srv/tfiles/backups
sudo install -d -o tfiles -g tfiles /srv/tfiles/logs
sudo install -d -o tfiles -g tfiles /srv/tfiles/storage
```

建議用途：

| 目錄 | 用途 |
| --- | --- |
| `/srv/tfiles/app` | 程式碼 |
| `/srv/tfiles/backups` | 暫存備份 |
| `/srv/tfiles/logs` | 應用程式紀錄 |
| `/srv/tfiles/storage` | 主機檔案儲存，僅在選擇本機磁碟時使用 |

### SSH 管理要求

正式主機應：

- 使用 SSH 金鑰登入。
- 禁止多人共用同一個管理帳號。
- 每位管理者使用自己的帳號。
- 只授予必要的 `sudo` 權限。
- 保存管理者加入及移除紀錄。
- 定期移除已離任成員的 SSH 金鑰。
- 在確認金鑰登入成功前，不要停用密碼登入。
- 不要直接開放 PostgreSQL 至公開網路。

### 防火牆要求

正式主機原則上只需要開放：

| 連接埠 | 用途 | 公開範圍 |
| --- | --- | --- |
| SSH 連接埠 | 主機管理 | 建議限制管理來源 |
| 80 | HTTP 重新導向 | 公開或只允許 Cloudflare |
| 443 | HTTPS | 公開或只允許 Cloudflare |
| PostgreSQL 5432 | 資料庫 | 不對外公開 |
| Node.js 程式連接埠 | Nginx 連接 | 只監聽 `127.0.0.1` |

防火牆實際指令需要依主機服務商及現有網路規則決定。

### 建立資料庫及使用者

以下名稱為建議值：

```text
資料庫：tfiles
使用者：tfiles_app
```

先產生安全密碼，再進入 PostgreSQL：

```bash
sudo -u postgres psql
```

在 PostgreSQL 中執行：

```sql
CREATE ROLE tfiles_app
    LOGIN
    PASSWORD '請替換為安全密碼';

CREATE DATABASE tfiles
    OWNER tfiles_app
    ENCODING 'UTF8'
    TEMPLATE template0;
```

完成後離開：

```sql
\q
```

注意：

- 不要把真正密碼寫入本文件。
- 不要把密碼提交到 GitHub。
- 正式程式不應使用 PostgreSQL 超級使用者。
- PostgreSQL 應只監聽本機或受限制的內部網路。
- 程式帳號只應擁有 `tfiles` 資料庫所需權限。

### PostgreSQL 連線環境變數

## PM2

狀態：`設定範本已完成，啟動指令待實作`

PM2 用來：

- 在背景執行 Node.js。
- 程式異常時重新啟動。
- 查看程式狀態。
- 查看應用程式紀錄。
- 主機重新開機後恢復網站。

安裝 PM2：

```bash
sudo npm install -g pm2
```

預定建立：

```text
/srv/tfiles/app/ecosystem.config.cjs
```

設定範本：

```javascript
module.exports = {
  apps: [
    {
      name: "tfiles",
      cwd: "/srv/tfiles/app",
      script: "待填寫正式啟動檔案",
      instances: 1,
      exec_mode: "fork",
      autorestart: true,
      watch: false,
      max_memory_restart: "512M",
      env: {
        NODE_ENV: "production",
        HOST: "127.0.0.1",
        PORT: "待填寫"
      }
    }
  ]
};
```

在正式啟動檔案及連接埠確定前，不可直接使用這份設定。

啟動：

```bash
sudo -u tfiles -H pm2 start /srv/tfiles/app/ecosystem.config.cjs
```

查看狀態：

```bash
sudo -u tfiles -H pm2 status
```

查看紀錄：

```bash
sudo -u tfiles -H pm2 logs tfiles --lines 200
```

儲存程序清單：

```bash
sudo -u tfiles -H pm2 save
```

設定開機啟動：

```bash
sudo -u tfiles -H pm2 startup
```

`pm2 startup` 會顯示一條需要使用 `sudo` 執行的指令。必須確認指令中的使用者是 `tfiles`、家目錄是 `/srv/tfiles`，再執行畫面提供的指令。

Node.js 升級後，需要重新執行 PM2 啟動設定。

## Cloudflare DNS

狀態：`網域已決定，主機 IP 待提供`

如果使用 Debian 主機，預計建立：

| 類型 | 名稱 | 內容 | Proxy |
| --- | --- | --- | --- |
| `A` | `file` | Debian 主機 IPv4 | Proxied |
| `AAAA` | `file` | Debian 主機 IPv6，沒有則不建立 | Proxied |

設定後的網址：

```text
https://file.tschoolsu.org
```

需要補入：

```text
Debian 主機 IPv4：待填寫
Debian 主機 IPv6：待填寫或不使用
Cloudflare Proxy：待確認
DNS 設定日期：待填寫
設定人員：待填寫
```

網站使用的 A、AAAA 或 CNAME 記錄建議開啟 Cloudflare Proxy。網域驗證、郵件驗證等 TXT 記錄不得誤設為 Proxy。

## HTTPS

狀態：`待選擇憑證方式`

可以選擇：

### Cloudflare Origin CA

適合：

- `file.tschoolsu.org` 永遠透過 Cloudflare Proxy。
- 不需要讓使用者直接連接來源主機。

需要：

- 在 Cloudflare 建立 Origin Certificate。
- 將憑證及私鑰安全放入 Debian。
- Nginx 使用該憑證。
- Cloudflare SSL/TLS 模式設為 `Full (strict)`。

建議路徑：

```text

/etc/ssl/tfiles/file.tschoolsu.org.key
```

### 公開信任憑證

可以使用公開憑證機構簽發的憑證。

適合：

- 需要直接連接來源主機。
- 不希望憑證只能由 Cloudflare 信任。

```text
Full (strict)
```

啟用前確認：

- 憑證尚未到期。
- 憑證包含 `file.tschoolsu.org`。
- Nginx 可以讀取憑證。
- 主機 443 連接埠可用。
- `nginx -t` 成功。

## 備份

狀態：`備份原則已完成，目的地及排程待決定`

備份必須包含：

### PostgreSQL 備份

建議使用 PostgreSQL custom format。先建立只有 PostgreSQL 系統帳號可寫入的備份目錄：

```bash
sudo install -d -o postgres -g postgres -m 700 /srv/tfiles/backups/postgresql
```

建立備份：

```bash
sudo -u postgres pg_dump \
  --format=custom \
  --file=/srv/tfiles/backups/postgresql/tfiles-日期.dump \
  tfiles
```

此格式需要使用 `pg_restore` 還原。

備份後必須確認：

- 指令成功。
- 備份檔案不是空檔。
- 備份已複製到另一個位置。
- 備份內容可以在測試環境還原。
- 備份錯誤會通知管理者。

### 檔案備份

如果使用 R2：

- 備份至另一個 Bucket 或其他儲存服務。
- 備份不能只保存在同一個帳號的同一個 Bucket。
- 定期測試取回檔案。
- 檢查資料庫中的儲存鍵是否能對應到實際檔案。

如果使用主機磁碟：

- 備份 `/srv/tfiles/storage/`。
- 備份應保存到另一台主機或另一個儲存服務。
- 不可只備份到同一顆硬碟。
- 必須同時備份目前檔案及歷史版本。

### 建議備份排程

| 項目 | 建議頻率 | 建議保留 |
| --- | --- | --- |
| PostgreSQL | 每日 | 30 天 |
| 檔案增量備份 | 每日 | 30 天 |

## 還原

狀態：`流程範本已完成，需在測試環境驗證`

先在新的測試資料庫驗證 PostgreSQL custom format 備份：

```bash
sudo -u postgres createdb --owner=tfiles_app tfiles_restore_test
sudo -u postgres pg_restore \
  --exit-on-error \
  --no-owner \
  --role=tfiles_app \
  --dbname=tfiles_restore_test \
  /srv/tfiles/backups/postgresql/tfiles-日期.dump
```

驗證完成後刪除測試資料庫：

```bash
sudo -u postgres dropdb tfiles_restore_test
```

3. 停止網站寫入。
4. 在測試資料庫驗證備份。
5. 確認 PostgreSQL 版本相容。
6. 還原資料庫。
7. 還原檔案或確認 R2 內容完整。
8. 啟動網站。
9. 測試登入、檔案、權限及版本。
10. 記錄還原時間、執行人及結果。

不要直接使用未驗證的備份覆蓋正式資料。

## 故障處理

### 網站完全無法開啟

依序檢查：

1. Cloudflare 是否有服務異常。
2. DNS 是否指向正確主機。
3. 主機是否可以連線。
4. Nginx 是否運作。
5. PM2 程式是否運作。
6. PostgreSQL 是否運作。
7. 主機磁碟是否已滿。
8. 憑證是否過期。
9. 防火牆是否阻擋連線。

檢查指令：

```bash
sudo systemctl status nginx
sudo systemctl status postgresql
sudo -u tfiles -H pm2 status
sudo -u tfiles -H pm2 logs tfiles --lines 200
df -h
```

### 出現 502 Bad Gateway

可能原因：

- Node.js 程式未啟動。
- PM2 持續重新啟動。
- Nginx 的程式連接埠錯誤。
- Node.js 只監聽錯誤的網路介面。
- 程式啟動失敗。

檢查：

```bash
sudo -u tfiles -H pm2 status
sudo -u tfiles -H pm2 logs tfiles --lines 200
sudo nginx -t
sudo ss -lntp
```

### 資料庫無法連線

檢查：

```bash
sudo systemctl status postgresql
sudo -u postgres pg_isready
```

確認：

- PostgreSQL 正在運作。
- `DATABASE_URL` 正確。
- 資料庫及使用者存在。
- 密碼正確。
- PostgreSQL 沒有對外公開。
- 主機磁碟尚有空間。
- 連線數沒有用盡。

### 無法上傳檔案

確認：

- Nginx `client_max_body_size`。
- 程式的單檔限制。
- 主機磁碟空間。
- R2 金鑰及 Bucket 權限。
- 上傳請求是否逾時。
- 程式是否仍在運作。
- 使用者是否有目的地資料夾的編輯權限。

### 無法下載檔案

確認：

- 使用者是否有存取權。
- PostgreSQL 中的儲存鍵是否存在。
- R2 或主機檔案是否存在。
- Nginx 是否中斷長時間下載。
- 程式紀錄是否顯示檔案不存在。
- 檔案是否已永久刪除。

### 無法寄信

確認：

- Brevo 服務狀態。
- `SMTP_HOST`。
- `SMTP_PORT`。
- `SMTP_USER`。
- `SMTP_PASSWORD`。
- 寄件者是否已驗證。
- 主機是否阻擋 SMTP 連線。
- 是否誤用 API key。
- Brevo 是否有額度或帳號限制。

可以優先測試 587；若主機阻擋，可測試 2525。

### 使用者無法登入

確認：

- 信箱是否為 `@tschool.tp.edu.tw`。
- 帳號是否已啟用。
- 帳號是否等待審核。
- 帳號是否被停用。
- SMTP 驗證信是否成功寄出。
- 密碼重設權杖是否過期。
- 登入是否觸發頻率限制。
- 主機時間是否正確。
- PostgreSQL 是否可以查詢帳號資料。

### 主機磁碟已滿

立即處理：

- 暫停上傳功能。
- 確認哪個目錄佔用空間。
- 不要直接刪除資料庫或檔案目錄。
- 不要直接清除仍在使用的版本檔案。
- 先確認備份完整。
- 清理可安全移除的暫存檔及過期紀錄。
- 擴充磁碟或將檔案搬至 R2。
- 記錄事件及處理方式。
